# SPACO 網站修改流程（2026-11-14 版）

寫俾 Heidi。呢份係「有嘢想改」時嘅標準做法：邊啲嘢你自己喺後台改就得、邊啲要改程式、改程式嘅步驟係點、出咗事點處理。

---

## 1. 先分清楚：後台改到 vs 要改程式

大部分日常改動已經唔需要改程式。先喺後台搵：

| 想改嘅嘢 | 去邊度 | 幾時生效 |
|---|---|---|
| 新分店／新房間、地址、容納人數、價錢、BBQ／飲品／提早入場價、房間關係（Room A/B/全層）、Google 日曆 ID、門鎖 ID、門鎖指引圖 | 後台 → **分店管理** | 儲存即時 |
| 附加服務開關、適用分店、價錢、菜單、到會菜式、水煙口味；**新增附加服務**（例如生日蛋糕） | 後台 → **附加服務管理** | 儲存即時；改價只影響之後新單 |
| 包場套餐（價錢、按金、時數、日子、包含項目、停售）；新分店要套餐 | 後台 → **套餐管理** →「複製到另一分店」 | 儲存即時 |
| 按金級別、固定按金扣款項目、積分比率、分期規則（條款同預訂須知會自動跟） | 後台 → **預訂規則** | 儲存即時 |
| 來源渠道（客人見到嘅）、行家／平台渠道、佣金 %、月結 Excel 要唔要獨立欄 | 後台 → 財務 → **來源渠道／佣金** | 儲存即時 |
| 固定開支、佣金手動改數、CS 底薪（按月生效）、獎金級別、利潤分配 | 後台 → 財務 → 支出管理／月結／CS 獎金 | 儲存即時 |
| 特別日子加價、最低人數、全場優先 | 後台 → **特別日子** | 儲存即時 |
| 門鎖連線測試、每間分店揀邊個鎖、密碼重發／撤銷 | 後台 → 系統管理 → **門鎖設定** | 即時 |
| 首頁相、分店相、文字、FAQ、文章、SEO | 後台 → 內容管理／常見問題管理／文章分享／SEO 管理 | 儲存即時 |
| 優惠碼、現金券（含一個碼多次用） | 後台 → 優惠碼 | 即時 |
| Email 自動化開關 | 後台 → 系統管理 → Email 自動化 | 即時 |
| Google 日曆連接／重新授權 | 後台 → 系統管理 → Google 同步 | 即時 |

**後台改唔到嘅**（要改程式）：新嘅計價方式、新嘅流程（例如新付款方式）、電郵內容格式、網頁版面、新嘅頁面、Firebase 規則、Vercel 環境變數（TTLock 帳戶、KPay 密鑰、Google client）。

## 2. 要改程式：每次都係呢個流程

1. **講清楚要改乜。** 一句講目的＋一個例子（邊張單、邊間分店、想見到點樣）。有截圖更好。
2. **我喺測試分支改。** 分支固定係 `claude/bold-goldberg-7zkepd`。每次改完會：
   - 行型別檢查（tsc）同全部自動測試（而家 579 個）；
   - 需要時喺本機 render 個頁面截圖睇吓；
   - 寫 commit，推上 GitHub。
3. **自動上測試站。** 推上去之後 Vercel 自動建置，兩三分鐘後 **https://spaco-test.vercel.app** 就係新版本。我會話你知個 commit 編號（例如 `978f8cd`）。
   - 測試站同正式站用**同一個資料庫**，所以測試站上面嘅訂單係真嘅——測試請用測試單（測試站開嘅單會自動標記 🧪，正式站唔會當佢阻時段，財務亦唔計）。
   - 唔好喺測試站做真付款。
4. **你試。** 用 Google 登入（測試站嘅網址已經授權咗，唔使再加）。有問題直接覆我，附截圖。
5. **你話「可以上」。** 我先會將同一個版本同步去正式站（`main`），Vercel 自動部署，幾分鐘後 spacohk.com 就係新版本。我唔會未經你批准就上正式站。
6. **Firebase 規則係另一條路。** 如果今次改動要改 Firebase 規則，我會另外講明，並俾你規則全文；你去 Firebase Console → Firestore → Rules 貼上並 Publish（先 copy 舊規則留底）。程式部署唔會自動改規則。
7. **Vercel 環境變數**（密鑰）同樣要你喺 Vercel → spaco-website → Settings → Environment Variables 自己加／改，改完要重新部署一次。

### 一次改幾樣
可以一次過講晒，我會分批做、分批推上測試站，每批報告一次。你可以逐批話「可以上」，亦可以等全部試完先一次過上。

### 緊急修正
正式站出事（例如客人訂唔到、付款確認唔到）：直接講「正式站 XXX 壞咗」。我會先查係咪設定問題（後台／規則／環境變數）再改程式；修正照樣先上測試站，但你可以即刻話「可以上」。

## 3. 出咗事點睇、點重試（唔使搵我）

- **取消／改狀態／按金結算** 做完如果有一步做唔到（例如 Google 日曆、門鎖、電郵），畫面會彈「⚠️ 未完成：……再做一次會重試」。再撳一次同一個動作就只會重試失敗嗰步，唔會重覆扣積分或者重發已經寄出嘅電郵。
- **付款後續工作**（KPay 收款後嘅確認電郵、門鎖、日曆、通知）失敗會自動重試，試足 6 次都唔得就停，staff 會收到一封電郵列明剩低要人手做嘅步驟；訂單詳情亦會標記。
- **門鎖密碼**每日 09:00 自動掃一次，失敗會寄電郵俾 staff。可以去 門鎖設定 睇上次結果、測試連線、對某張單手動產生／重發／撤銷。
- **Google 日曆**每 15 分鐘同步一次；去 Google 同步 可以睇上次結果同手動同步。
- **時段撞期**：系統而家會連自己嘅 60 分鐘清潔時間一齊檢查；如果補記錄舊單付款時時段已經賣咗，張單會標記「需要覆核」而唔會疊單。

## 4. 設定一覽：邊度係唯一來源

| 數據 | 唯一來源 | 備註 |
|---|---|---|
| 分店／房間 | 分店管理（資料庫） | 程式入面嘅舊四間分店清單只係後備 |
| 附加服務 | 附加服務管理（資料庫） | 程式內置清單係種子；自訂項目 ID 係 `x-…` |
| 套餐 | 套餐管理（資料庫） | 未儲存過之前跟程式內置 |
| 預訂規則 | 預訂規則（資料庫） | 條款、預訂須知由佢生成 |
| 來源渠道／佣金 | 來源渠道／佣金（資料庫） | 支出管理嘅佣金規則係同一份 |
| 門鎖 ID／指引圖／確認鍵 | 分店管理每間房 | 門鎖設定頁可以一撳搬舊設定 |
| TTLock 帳戶、KPay、Google client、CRON_SECRET | Vercel 環境變數 | 後台唔顯示值，門鎖設定只顯示「有冇設」 |
