### Remaining doubled title on production is GloMap, not the site

After the release, spacohk.com still showed 「SPACO · SPACO」 in the tab a few seconds after load, while the preview did not. Server HTML and RSC payloads for both are identical and contain no brand template. The production-only GloMap embed (`glomap.vercel.app/api/embed/.../glomap.js`) fetches `/meta?url=<page>` and, when a title is returned, sets `document.title` and the og/description metas. GloMap's stored titles for /zh, /en and /zh/articles are the old doubled strings (verified by calling the endpoint directly); /zh/faq returns a clean title and is not doubled. Fix belongs in GloMap (update the stored title or let it re-crawl); alternatively stop GloMap from injecting metadata. Search engines read the server HTML, which is correct.
